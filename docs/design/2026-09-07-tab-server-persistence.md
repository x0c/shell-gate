# Tab 服务端记忆（跨刷新 / 跨浏览器）

Current standalone provider defaults and import rules are defined in [deployment](../DEPLOYMENT.md). Infrastructure choices in this earlier design are optional deployment examples, not mandatory dependencies.
> 2026-09-07 产品意图落盘。实现、评审或改 Tab 恢复逻辑前**必读**。

## 产品意图

登录同一白名单账号后，工作台的 Tab 集合由**服务端按账号记忆**，不依赖某个浏览器窗口的临时状态：

1. **刷新页面**：仍看到同一组 Tab，并接回各自的终端会话意图（见下节「接回语义」）。
2. **换浏览器 / 换设备再登录**：仍看到同一组 Tab，与此前打开的一致。
3. **只有在工作台里明确关掉某个 Tab**，才从账号记忆里删掉；关网页、锁屏、切后台、异常退出都不得清空。
4. **首次进入且账号下没有任何 Tab** 时，才自动开一个空 shell；若账号下已有 Tab，禁止再暗中新开空终端。

这推翻此前两条口径：

- 「关 Tab 即结束、不做会话持久（断线接回交给 Corral）」里「不做会话持久」的 Tab 目录部分——**Tab 目录要持久**；程序级接回仍可交给 Corral 等应用自己。
- 「刷新只恢复本浏览器窗口已有 Tab、别把其它设备的窗口塞进当前工作台」——改为**账号下只有一套共享工作台**。

## 接回语义（2026-09-07 已确认）

**不改 Corral、不绑死任何预置。** 门禁只做通用能力：按账号记住 Tab（机器 / 标题 / 启动命令），再连时重新注入同一条启动命令。若某个程序自己会接回会话，那是它自己的行为；门禁不为此特判。

| 类型 | 刷新 / 换浏览器后实际效果 |
|---|---|
| 自带会话接回的程序（例如 Corral） | 按其既有接回逻辑回到原会话；门禁无特判 |
| 普通空 shell / 一次性命令落回的交互壳 | **滚动历史与未退出前台进程不保证还在**；同一台机器、同一启动方式的新壳 |

不做「每 Tab 一条进程级中继 / tmux」；那是另一项产品。

## 实现口径

- 服务端按邮箱持久保存 Tab（写入共享 Postgres `shell_gate` 库，见 [双入口共享存储](2026-09-08-dual-edge-shared-store.md)；重启门禁不丢目录）。
- 登录后工作台一律从服务端拉全量账号 Tab 挂载；本机只额外记住「当前选中哪一个 / 哪台机器 / **每台机器上次激活的 Tab**」之类的展示偏好即可（切机恢复见 [多上游机器支持](2026-08-24-multi-upstream.md) §6）。
- 明确关闭 Tab：删服务端记录，并释放该 Tab 的 Mac 睡眠租约（若有）。
- 浏览器异常消失：Tab 目录保留；Mac 租约仍按既有最长 8 小时自毁，避免永久占电。门禁进程重启后，对库里仍在的 Mac Tab 重新申请租约。
- 多设备同时打开同一 Tab：各自连上游（各起一条进程）；不以「抢唯一 PTY」为第一期目标。

## 与现网的差距

| 现状 | 目标 |
|---|---|
| Tab 只在门禁进程内存里 | 落库，重启仍在 |
| 前端用窗口级临时状态过滤，只恢复「本窗口开过的」 | 恢复该账号下全部未关闭 Tab |
| 换浏览器常被当成「首次进入」再开空 shell | 有记忆则只挂载记忆，不开新壳 |
| 文档写「不做会话持久」 | 改为账号级 Tab 记忆 + 上表接回语义 |

## 验收

1. 开若干 Tab（含不同机器与预置）→ 刷新 → Tab 条与选中态一致，且未多出一个空 shell。
2. 同一账号在另一浏览器登录 → 看到同一组 Tab，未多开空 shell。
3. 在一端关掉某个 Tab → 另一端刷新后该 Tab 消失。
4. 门禁进程重启后 → Tab 目录仍在；Mac 有 Tab 时租约行为符合 [Mac 上游指南](../MAC_UPSTREAM_GUIDE.md)。
5. 账号下零 Tab 的首次进入 → 仍自动开一个空 shell。
