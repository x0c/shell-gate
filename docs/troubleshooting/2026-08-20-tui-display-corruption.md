# TUI 乱码 / 中文消失：WebGL 图集与渲染器选择

网页终端（尤其 Corral 这类全屏 TUI）用着用着出现错位字符、中文消失、中文变成怪字，**拖一下窗口边缘就好**。不是链路，也不是远端程序把缓冲区写乱了。

**【裁定 2026-08-31】** 使用中画面必须保持正确。禁止把 Ctrl/Cmd+Shift+K /「修复显示」当产品路径。默认渲染器改回 `canvas`，接受绘制段大约 44ms 的回退，换中文不丢。下面「自愈」章节是 WebGL 被重新打开时的双保险，不是给用户用的修法。

## 先分清是哪一种「乱码」

| 信号 | 判断 |
|---|---|
| 调窗口恢复，复制/截图里的字有时是对的，或「修复显示」能好 | 画面层贴图过期，走本页这条 |
| 调窗口恢复，但内容排版整块错位、程序也跟着重排 | 更像 SIGWINCH / 尺寸不一致，不是贴图 |
| 一直错、调窗口也不好 | 不是这条；先看上游 ttyd 是否还活着、Tab 是否在重连死循环 |

用户原话「类似乱码、调窗口恢复、像渲染框架固有问题」对的是第一行。

## 根因

xterm.js WebGL 把字形画进纹理图集再复用。TUI 高频整屏重绘会触发：

1. **贴图页合并后顶点还指着旧坐标**（[#6038](https://github.com/xtermjs/xterm.js/issues/6038) 的共享图集路径；单 iframe 单终端也会在页合并时踩同类失步）
2. **图集页数顶满**（同 issue 的 overflow；CJK + 多色 TUI 很容易堆）

缓冲区是对的，画出来是错的。resize 会整套重建贴图，所以看起来「拉一下窗口就好」。

**勘误（不要再写 7.0.0）**：#6038 已于 2026-07 合入 `@xterm/xterm` **6.1.0-beta.289** / `@xterm/addon-webgl` 0.20.0-beta.288。ttyd 1.7.7 捆的是 xterm **5.4.0**；6.0 正式版也还没有这补丁。门禁换不了这份内置 xterm（webpack 打进二进制），所以 2026-08-31 起默认走 canvas，不走这条图集路径。

## 为什么 v0.5.0 上线了还会频繁出现

已发布、门禁节点二进制也对，**不是没发**。v0.5.0 的自动修复只挂了：

- 页签回到前台（`visibilitychange`）
- 屏幕缩放 / 跨屏（`devicePixelRatio`）
- 手动：Ctrl/Cmd+Shift+K，窄屏「⋯ → 修复显示」

乱码发生在 **TUI 正在刷屏时**。人不切后台、不改缩放、桌面又没有常驻按钮，自愈一次都不会跑，只能继续调窗口。这是触发条件没盖住主路径，不是 `clearTextureAtlas()` 没打进包。

2026-08-20 补 `installFullRedrawRepair`：

- 1 秒内 ≥2 次大半屏重绘 → 爆发，安静 180ms 后重建贴图
- 爆发持续超过 2.5s → 不等安静，强制修一次
- 只有一次整屏（之后只剩 Corral 那种 2s 空闲查询）→ 8s 懒修；已有定时器不重计，避免被心跳冲掉
- `full-redraw` 埋点 15s 最多一条，避免刷 `debug-log.ndjson`

手动入口仍然有效，只是不应再当主路径。2026-08-31 起连这条主路径也不够，见下节。

## 2026-08-31：自愈盖不住「用着用着中文消失」，默认改回 canvas

用户原话：只是使用 Corral 的 TUI、没有动窗口，中文消失或变成奇怪展示；不要用快捷键修，这种问题本身就不该发生。

### 为什么 8 月 20 日那套自愈仍然会看见乱码

`installFullRedrawRepair` 是**事后**调 `clearTextureAtlas()`。即便触发到了，用户已经看见过一帧（甚至一直挂着）坏字。

更关键的是触发条件对不上 Corral 的真实刷屏形态：

- 判定「整屏」要 `span * 2 >= rows`（一半以上行被重绘）。Corral 流式刷中文、局部刷新聊天区，经常只脏几行，**根本不进爆发路径**。
- 进了「一次整屏」才走 8s 懒修。人已经对着坏了的中文看很久。
- 爆发路径还要 180ms 安静 / 最长等 2.5s。流式输出期间定时器被不断推迟。

所以「用着用着就乱码、没调窗口」完全可以发生，不是自愈没打进包。

中文特有指纹与 [WaveTerm #3386](https://github.com/wavetermdev/waveterm/issues/3386) 一致：大量互异 CJK 字形把 WebGL 图集挤爆后，宽字符（占 2 格）槽位 LRU 驱逐时左右半格不能原子清空，画面上像两半字叠在一起或直接「没了」。复制出来的文本是对的；关掉 WebGL 即不再现。#6038 的页合并/溢出是同一类图集病，不是另一件事。

### 方案对比（门禁侧能做的）

| 方案 | 中文还会坏吗 | 代价 | 结论 |
|---|---|---|---|
| 再加触发点 / 周期性 `clearTextureAtlas` | 会。只是把窗口从「一直挂着」收成「闪一下」 | 空闲也会卡 | **否决**。用户要的是不发生，不是修得更勤 |
| 注入 `@xterm/addon-webgl` 0.20+（带 #6038） | 理论上能 | 0.20 对 xterm **6.x**，ttyd 捆的是 **5.4.0**，API 对不上 | **否决** |
| 反代整页换成我们自己的 xterm 6 前端 | 能，还能保住 WebGL 速度 | 重写 ttyd 的 WS/鉴权/token 客户端 | 工作量过大，不作为这次的修法 |
| 升级终端节点 ttyd | **不能**。ttyd **master** 仍是 `@xterm/xterm@5.5.0` + `addon-webgl@0.18.0`，没有 6.1 那批补丁 | 要 root、且升了也还是这条 bug | **否决**（别指望升 ttyd 消乱码） |
| 默认 `rendererType=canvas` | **不会**（canvas 不走 GPU 图集） | 绘制段 P50 70ms / P95 102ms，相对 WebGL 的 26 / 44ms，大约 +44ms | **采用** |

ttyd 1.7.7 已经带 `@xterm/addon-canvas`，`setRendererType('canvas')` 是一等公民；门禁 iframe 的 URL 查询参数优先于上游 `-t`，改 `workspace.html` 的 `iframe.src` 即可，不必动终端节点 root 单元。

### 接受的代价（不是 bug，别去「优化」回来）

2026-08-05 换成 WebGL 是为了把「回显到达→画面绘制」从 P50 70ms 降到 26ms。那次优化成立，但建立在「ASCII 空 shell 打字」上。Corral 全屏 TUI 大量按键根本不触发重绘，那 44ms 换来的是中文用着用着就坏。

**【裁定】** 中文正确优先于那 44ms。禁止为了绘制延迟把默认改回 `webgl`，除非上游 ttyd 捆到带宽字符图集修复的 xterm（≥6.1.0-beta.289 **且**用 CJK 洪泛脚本验证过不再花屏）。

canvas 下选区仍必须走 8 位 alpha 的 `selectionBackground`（xterm #2737/#2808）。`preserveDrawingBuffer` 补丁保留：有人强制 webgl、或上下文丢失回落时，截图还靠它。

## 改这块时不要做的事

- **不要把默认 `rendererType` 改回 webgl 来「找回 44ms」。** 见上节裁定。
- **不要用 `term.resize()` / `fit()` 冒充修复。** 那会 SIGWINCH，正在跑的 TUI 会整页重排；贴图重建不得打扰 PTY。
- **不要在 `onRender` 回调里同步调 `clearTextureAtlas()`。** 那是当前帧画到一半，必须 `setTimeout` 挪到帧后。
- **不要对 Corral 每 2s 的空闲查询每次都重建。** 那会变成空闲周期性卡一下。
- **不要再靠加自愈触发点消乱码。** 自愈是 WebGL 被重新打开时的双保险；产品路径是 canvas。

## 真要根治（仍想要 WebGL 速度时）

等上游 ttyd 捆到带宽字符图集修复的 xterm（≥6.1.0-beta.289，并做 CJK 洪泛验收），或门禁侧愿意重写 ttyd 前端。届时自愈降级为双保险，**不要删**——DPR / 睡眠唤醒官方仍建议保留 `clearTextureAtlas` 入口，同族 bug 也复发过。
